# Разработка cutover-плана

## Анализ текущей ситуации


### Существующая система

- Монолит: Все данные в Excel/JPG/PDF на общем диске Windows Server 2022
- Интеграции: Ручные, через копирование данных между Excel-файлами
- Данные: Неструктурированные, без валидации, доступны всем в домене
- Команда: 3 IT-специалиста

### Новая архитектура

- Микросервисы: Administrator Service, Medical Specialist Service
- Технологии: Java/Postgres/Kubernetes/Keycloak/Vault

## Обоснование выбора стратегии параллельного запуска

- Главное преимущество parallel run в сравнении с другими подоходами -- минимизация рисков. В случае любого сбоя новой системы, снижения производительности и т.д. -- всегда можно подстраховаться и работать в старой системе.
- Минимальный риск потери данных, т.к. они по факту дублируются в обеих системах
- Минимальный риск сбоев интеграции, т.к. старая интеграция всё ещё работает.
- Постепенный перевод сотрудников на новую систему, при этом часть сотрудников может продолжать работать в старой системе.
- В случае сбоев новой системы чинить их не придется в авральном режиме, т.к. всегда можно переключиться на старую систему.
- Высока вероятность сбоев новой системы, т.к. IT-команда не большая, и, возможно, в ней не хватает навыков.
